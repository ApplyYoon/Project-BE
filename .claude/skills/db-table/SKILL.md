# 테이블(엔티티) 만들기

## 1. 설계는 학생이 합니다

이 프로젝트에서 **테이블 설계는 학생이 직접 하는 공부**입니다.
당신이 테이블과 컬럼을 먼저 정해 주면 그 공부가 사라집니다.

- **먼저 제안하지 마세요.** "이런 컬럼이 필요해요" 라고 답을 주지 않습니다.
- 대신 **질문으로** 돕습니다. 한 번에 하나씩.
  1. 이 테이블에는 무엇 하나가 한 줄이 되나요? (예: 메모 하나)
  2. 그 한 줄에 어떤 정보를 적어야 하나요?
  3. 누구의 것인지는 어떻게 알 수 있나요?
  4. 꼭 있어야 하는 값과 비어 있어도 되는 값은 무엇인가요?
  5. 다른 테이블의 무엇과 이어지나요?
- 학생이 정한 것을 **코드로 옮기는 일**은 도와줍니다.
- 아래 규칙에 어긋나면 **이유를 설명하고** 고칠지 물어봅니다. 그래도 하겠다면 그대로 해 줍니다.
- FE 와 이름을 맞춰야 하면 FE 의 `src/types/index.ts` 를 같이 보자고 합니다. (FE 타입을 고치는 쪽이 나으면 그렇게 제안해도 됩니다)

## 2. 엔티티 규칙 (CLAUDE.md 3장)

- 필드는 camelCase — DB 컬럼은 snake_case 로 알아서 바뀝니다 (`userId` → `user_id`)
- 필드마다 **한국어 주석** 한 줄
- 시각은 `Instant`, 날짜는 `LocalDate`
- `users` 를 뺀 모든 테이블에 `userId` — 누구의 데이터인지 항상 알 수 있어야 합니다
- `@Setter`, `@Data` 금지. `@Getter` + `@NoArgsConstructor(access = AccessLevel.PROTECTED)` + 직접 만든 생성자
- `user`, `date`, `order` 같은 **DB 예약어**는 이름으로 쓰면 에러가 납니다 → `@Table(name = "users")`, `planDate`
- 정해진 값만 들어가는 컬럼은 `enum` + `@Enumerated(EnumType.STRING)`

예시 모양은 `docs/FOLDER-STRUCTURE.md` 의 "엔티티" 부분에 있습니다.

## 3. 만든 뒤 — **매번** 그림으로 확인합니다

엔티티를 만들거나 고칠 때마다 아래를 합니다.

1. 서버를 다시 켭니다 (`./gradlew bootRun`). 테이블은 **켤 때** 만들어집니다.
2. 실제로 만들어진 모양을 확인하게 안내합니다.
   > http://localhost:8080/h2-console 을 열고 `JDBC URL` 에 `jdbc:h2:mem:projectbe`, `User Name` 에 `sa` 를 넣고 Connect.
   > 왼쪽에 방금 만든 테이블이 보이면 눌러서 컬럼을 확인해 보세요.
3. **`/db` 의 순서대로 다이어그램을 새로 그려** 브라우저로 보여 주고, `docs/DB.md` 에도 반영합니다. (`.claude/commands/db.md`)
4. 그림을 보며 학생에게 묻습니다. "생각한 모양과 같나요? 선이 이어져야 하는데 안 이어진 곳은 없나요?"

`docs/DB.md` 의 그림 변경은 엔티티와 **같은 커밋**에 넣습니다.

## 4. 주의

- 로컬 DB(H2)는 서버를 끄면 데이터가 사라집니다. 컬럼을 바꿔도 옛 데이터 걱정은 없습니다.
- 운영 DB(Neon)는 아직 연결 전입니다. 연결한 뒤에는 테이블을 바꿀 때 Neon 쪽 작업이 따로 필요합니다 — 그때 이 문서를 고칩니다.
- 테이블을 지우는 일(`DROP`)과 엔티티 파일 삭제는 반드시 먼저 물어봅니다.
