# 예약 작업 가이드

사람이 요청하지 않아도 **정해진 시각에 서버가 일을 하게** 만드는 방법입니다. (이슈 #9)
예: 매일 밤 하루 요약표 만들기(#34), 계획 시간이 지났는데 타이머가 꺼져 있으면 메시지 보내기(#31)

> ⚠️ **이 문서의 코드와 규칙은 로컬에서 테스트로 확인했습니다. 하지만 실제 배포 서버(Render)에서 돌려 본 것은 아닙니다.**
> [6. 배포 서버에 연결하기](#6-배포-서버에-연결하기-사람이-합니다) 는 순서만 적었고, 직접 해 본 뒤 막힌 점은 이 문서에 추가해 주세요.

---

## 1. 어떻게 돌아가나

서버는 스스로 시계를 보고 일어나지 않습니다. 대신 **서버가 "작업 주소"를 열어 두고, 바깥의 스케줄러(알람 시계)가 정해진 시각에 그 주소를 불러 줍니다.**

```
cron-job.org (알람 시계)                         Render 의 BE 서버
  10분마다  ──  POST /api/v1/jobs/practice  ──▶  ① 문지기: X-Job-Key 가 맞나?  (틀리면 401)
              헤더  X-Job-Key: <비밀 키>          ② 실행기: 같은 작업이 이미 도는 중인가? (그러면 건너뜀)
                                                 ③ 작업 실행 → 로그 한 줄 + 결과를 "그날 한 칸" 에 덮어쓰기
              ◀──────  200 { "status": "DONE" }
```

**왜 서버 안에 알람을 두지 않았나?** 무료 서버는 15분 동안 요청이 없으면 **잠듭니다.** 잠든 서버는 알람을 울릴 수 없습니다. 바깥 스케줄러가 부르면 서버가 깨어나고, 10분마다 부르면 아예 잠들 틈이 없습니다. (비교한 다른 방법은 [README 의 "예약 작업"](../README.md#-예약-작업) 에 있습니다)

## 2. 코드는 어디에 있나

| 파일 (`src/main/java/com/ithopeschool/projectbe/…`) | 하는 일 |
| ------------------------------------------------------ | ------- |
| `domain/job/JobKeyInterceptor.java` | **문지기.** `/api/v1/jobs/**` 로 오는 요청의 비밀 키를 먼저 확인 |
| `domain/job/JobWebConfig.java` | 문지기를 `/api/v1/jobs/**` 에 연결 |
| `domain/job/JobController.java` | `POST /api/v1/jobs/{name}` — 작업을 부르는 주소 |
| `domain/job/JobRunner.java` | 이름으로 작업을 찾아 실행. **같은 작업이 겹쳐 돌지 않게** 막고, 실패해도 서버는 그대로 둠 |
| `domain/job/ScheduledJob.java` | 작업 하나의 "약속" (이름 + 실행). 새 작업은 이걸 구현 |
| `domain/job/PracticeJob.java` | 연습 작업. 로그 한 줄을 남김 |
| `domain/push/HabitNudgeJob.java` | `habit-nudge` 작업. 하루 한 번 "오늘의 작전" 알림 (아래 6-4) |
| `domain/job/JobResultStore.java` | 결과를 "작업 이름 + 날짜" 한 칸에 **덮어써서** 저장 (연습용 메모리 저장소) |
| `global/time/DayRule.java` | **하루의 기준(새벽 4시, 한국 시간)** 계산기. 날짜별로 세는 곳은 모두 이걸 씀 |
| `global/config/ClockConfig.java` | 시계. 테스트에서 시간을 고정하려고 따로 둠 |

## 3. 비밀 키

아무나 작업 주소를 불러 작업을 마구 돌리면 안 되니, **요청마다 비밀 키를 확인**합니다.

| 항목 | 값 |
| ---- | -- |
| 헤더 이름 | `X-Job-Key` |
| 서버 설정 | `app.job.secret-key` ← 환경변수 **`JOB_SECRET_KEY`** |
| 내 컴퓨터(로컬) 키 | `local-job-key` (`application-local.yml`. 로컬에서만 통하는 값이라 올려도 됩니다) |
| 배포 서버 키 | **진짜 키는 어떤 파일에도 적지 않습니다.** Render 설정 화면에만 넣습니다 |

규칙 (모두 테스트로 확인했습니다)

- 헤더가 없거나, 키가 틀리거나, **한 글자라도 다르면** `401`. (대소문자·공백·길이가 다른 거의-맞는 키도 거절)
- **서버에 키가 설정되지 않았으면 "모두 허용"이 아니라 "모두 거절"** 입니다. 설정을 깜빡해도 문이 열리지 않습니다. (서버 로그에 경고가 한 줄 나옵니다)
- 키를 **주소(`?key=…`)나 다른 헤더**에 넣으면 통과하지 못합니다.
- `/api/v1/jobs/` 아래는 **어떤 주소든** 보호됩니다. 주소를 살짝 바꿔(`%6Aobs`, `;`, 끝의 `/`) 피하려 해도 막힙니다.
- 키가 없으면 없는 작업도 `404` 가 아니라 `401` 입니다. (어떤 작업이 있는지 새어 나가지 않게)
- 키는 로그나 응답에 **절대 찍지 않습니다.**

### 키 만들기

추측할 수 없는 긴 글자여야 합니다. 아래 중 하나로 만들고 **화면에 한 번만 보고 바로 Render 에 붙여 넣으세요.**

```powershell
# Windows PowerShell
$b = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
($b | ForEach-Object { $_.ToString('x2') }) -join ''
```

```bash
# Mac / Linux / Git Bash
openssl rand -hex 32
```

64자리 글자가 나옵니다. **이 값을 코드·`render.yaml`·이슈·PR·채팅·스크린샷 어디에도 쓰지 않습니다.** 실수로 적었다면 바로 팀장에게 알리고 **새 키로 바꾸세요.** (Render 와 cron-job.org 두 곳을 같이 바꿉니다)

## 4. 내 컴퓨터에서 시험하기

서버를 켜고(`./gradlew bootRun`) 다른 터미널에서 불러 봅니다.

```bash
# 키가 맞을 때 → 200
curl -i -X POST http://localhost:8080/api/v1/jobs/practice -H "X-Job-Key: local-job-key"

# 키가 없거나 틀릴 때 → 401  (작업은 실행되지 않습니다)
curl -i -X POST http://localhost:8080/api/v1/jobs/practice
curl -i -X POST http://localhost:8080/api/v1/jobs/practice -H "X-Job-Key: wrong"
```

- 서버를 켠 터미널에 `[연습 작업] 실행됐어요. 기준 날짜=…, 시각=…` 한 줄이 쌓이면 성공입니다.
- **두 번, 열 번 불러도** 응답과 결과가 같습니다. (결과는 그날 한 칸을 덮어쓸 뿐입니다)
- Swagger(`http://localhost:8080/swagger-ui.html`)에서도 불러 볼 수 있습니다. "예약 작업" 에서 **`X-Job-Key` 칸에 `local-job-key`** 를 넣으세요.

## 5. 새 작업 만드는 법

1. `domain/job/` 아래에 `ScheduledJob` 을 구현한 클래스를 만들고 `@Component` 를 붙입니다.
2. `name()` 에 주소에 쓸 이름(소문자·숫자·하이픈)을 적습니다. → `POST /api/v1/jobs/<이름>` 으로 불립니다.
3. `run(JobContext)` 에 할 일을 씁니다. 키 확인·겹침 방지·실패 처리는 **이미 되어 있으니 다시 만들지 않습니다.**

```java
@Component
public class DailySummaryJob implements ScheduledJob {
  @Override public String name() { return "daily-summary"; }
  @Override public void run(JobContext context) {
    // context.date() 가 기준 날짜(하루의 기준 새벽 4시)입니다. 그 날짜의 요약을 "덮어쓰기" 로 저장합니다.
  }
}
```

### ✅ 작업을 만들 때 지킬 것

| 규칙 | 이유 |
| ---- | ---- |
| **두 번 돌아도 결과가 같아야 합니다.** 결과는 "추가"가 아니라 **그날 것을 덮어쓰기**(DB 라면 날짜로 upsert)로 저장 | 스케줄러가 실패해서 다시 부르거나, 두 곳에서 부를 수 있습니다 |
| "몇 번째 실행" 같은 **매번 달라지는 값을 결과에 넣지 않기** | 넣으면 두 번 돌릴 때마다 결과가 바뀌어 "같은 결과"가 아니게 됩니다 |
| 날짜는 `context.date()` / `DayRule` 로만 계산 | 자정 기준으로 세는 곳이 하나라도 있으면 숫자가 서로 안 맞습니다 (`docs/API.md` 2-4) |
| **지난 날짜를 다시 만들어도 안전**하게 | 기록을 고쳤을 때 다시 만들 수 있어야 합니다 (#34) |
| **짧게** 끝내기 (30초 안) | 스케줄러는 30초까지만 기다립니다. 오래 걸리면 나눠서 합니다 |
| 실패는 **예외를 던지기** | 실행기가 `500` 으로 알려서 스케줄러가 실패를 알아채고 이메일을 보냅니다 |
| 로그에 **일기·기분·통화 내용, 비밀값을 찍지 않기** | CLAUDE.md 4장 |

## 6. 배포 서버에 연결하기 (사람이 합니다)

> 선행: **#8 배포가 끝나서** 서버 주소가 있어야 합니다. (`docs/DEPLOY.md`) 그 전에는 로컬 시험(4번)까지만 됩니다.

### 6-1. Render 에 키 넣기

1. 위 [키 만들기](#키-만들기)로 키를 만듭니다.
2. Render 대시보드 → 서비스 `project-be` → **Environment** → **Add Environment Variable**
   - Key: `JOB_SECRET_KEY` / Value: 방금 만든 키
3. 저장하면 서버가 다시 시작됩니다. (`render.yaml` 에는 이 줄이 아직 없어서 **화면에서 직접 추가**해야 합니다)
4. 확인: 키 없이 불러 보면 **401**, 키를 넣으면 **200** 이어야 합니다.

```bash
curl -i -X POST https://<받은 주소>/api/v1/jobs/practice                      # → 401
curl -i -X POST https://<받은 주소>/api/v1/jobs/practice -H "X-Job-Key: <키>"  # → 200
```

### 6-2. cron-job.org 에서 알람 만들기

1. https://cron-job.org 에서 가입합니다. (카드를 요구하는지는 공식 문서에 없습니다. **요구하면 멈추고 팀에 알리세요**)
2. **Create cronjob** 으로 새 작업을 만들고 아래처럼 채웁니다.

| 칸 | 값 |
| -- | -- |
| URL | `https://<받은 주소>/api/v1/jobs/practice` |
| 실행 주기 | **10분마다** (Every 10 minutes) |
| 요청 방법 | **POST** (고급 설정의 request method) |
| 헤더 | 이름 `X-Job-Key`, 값 = Render 에 넣은 **같은 키** |
| 실패 알림 | 켜기 (실패하면 이메일) |

> 위 칸 이름과 화면 순서는 일반적인 모양으로 적은 것이고 **직접 해 보지 않았습니다.** 화면이 다르면 "URL · 10분마다 · POST · 헤더 `X-Job-Key`" 만 맞추면 됩니다.

### 6-3. 돌고 있는지 확인 (완료 조건)

- Render 서비스의 **Logs** 에 `[연습 작업] 실행됐어요` 가 **10분 간격으로** 한 줄씩 쌓이는지 봅니다.
- cron-job.org 의 실행 기록에서 응답이 `200` 인지 봅니다.
- 연습이 끝나면 cron-job.org 의 연습 작업을 **끄거나 지웁니다.** (로그만 계속 쌓이고, 서버가 안 잠들어 무료 시간을 씁니다 — 아래 7번)

### 6-4. "오늘의 작전" 알림 (`habit-nudge`)

알림을 켠 학생에게 **하루 한 번** 생각 습관에 맞춘 한 줄을 웹 푸시로 보냅니다. (이슈 #32, `domain/push/HabitNudgeJob.java`)

> 선행: Render 에 **VAPID 키**가 있어야 합니다. (`docs/DEPLOY.md` "웹 푸시 켜기") 없으면 앱 알림 목록에는 남고 푸시만 안 갑니다.

| 칸 | 값 |
| -- | -- |
| URL | `https://<받은 주소>/api/v1/jobs/habit-nudge` |
| 실행 주기 | **매일 저녁 7시** (한국 시간). 시간대를 `Asia/Seoul` 로 맞추세요 |
| 요청 방법 | **POST** |
| 헤더 | 이름 `X-Job-Key`, 값 = Render 에 넣은 **같은 키** |

학생마다 아래를 차례로 보고, 하나라도 걸리면 그 학생은 건너뜁니다.

1. **연락 금지 시간(밤 11시 ~ 아침 7시)** 이면 아무에게도 보내지 않습니다. (시각을 잘못 맞춰도 밤에는 안 갑니다)
2. **오늘(새벽 4시 기준) 이미 보냈으면** 보내지 않습니다. 스케줄러가 두 번 불러도 한 번만 갑니다.
3. **최근 7일 안에 위기 표현이 감지된 통화**가 있으면 보내지 않습니다. 공부를 재촉하는 말을 멈춥니다.
4. 한 줄 고르기: 저장된 생각 습관 테스트에서 가장 높은 습관 → 없으면 최근 2주 통화에서 가장 최근에 보인 습관 → 없으면 기본 문장
   - 예: "다음 계획은 처음 예상한 시간의 1.5배로 잡아 보기 (계획 오류 대비)" / 기본 "오늘 계획 하나, 5분만 먼저 시작해 볼까?"
   - 문장은 생각 습관 목록에 정해 둔 것이라 AI 가 지어내지 않습니다.
5. 앱의 **알림 목록(messages, 종류 `NUDGE`)에 먼저 남기고**, 그 학생의 모든 기기에 푸시를 보냅니다. 누르면 타이머가 열립니다.

- 로그에는 `[오늘의 작전] 보냄 n명 · 건너뜀 n명` 처럼 **숫자만** 남깁니다. 알림 내용은 찍지 않습니다.
- ⚠️ 학생이 설정에서 정한 연락 금지 시간·메시지 빈도는 아직 서버에 없어서(#22) 기본값(23 ~ 7시, 하루 한 번)을 씁니다.
- ⚠️ 체크인의 기분·시험 기간은 아직 브라우저에만 있어서, 안전 브레이크 중 "위기 표현이 있던 통화" 만 봅니다.
- ⚠️ 한 학생에게 보내는 데 최대 10초(응답 기다리기)가 걸릴 수 있어서, 학생이 아주 많아지면 30초 안에 못 끝날 수 있습니다. 그때는 나눠서 보내게 고쳐야 합니다.

**내 컴퓨터에서 시험** — 푸시는 꺼져 있지만, 알림 목록에 남는 것은 볼 수 있습니다.

```bash
curl -i -X POST http://localhost:8080/api/v1/jobs/habit-nudge -H "X-Job-Key: local-job-key"
```

알림을 켠 학생(구독)이 있어야 대상이 됩니다. 구독은 FE 의 "알림 받기" 버튼이나 Swagger 의 `POST /api/v1/push/subscriptions` 로 만듭니다.

## 7. 알아 둘 점

- **서버가 잠들지 않게 됩니다.** 10분마다 부르면 15분 유휴 규칙에 걸리지 않아 서버가 계속 깨어 있습니다. Render 무료 인스턴스는 월 750시간이고 한 달(31일)이 744시간이라 **서비스 하나는 한 달 내내 켜 둬도 한도 안**이지만, 거의 다 쓰게 됩니다.
- **서버가 자고 있을 때 부른 첫 요청은 실패할 수 있습니다.** 깨어나는 데 약 1분(+자바가 켜지는 시간)이 걸리는데 cron-job.org 는 **30초**까지만 기다립니다. 그 요청이 서버를 깨우고, 다음 호출부터 정상이어야 합니다. (실제로 해 본 것은 아닙니다)
- 스케줄러가 연속으로 많이 실패하면 cron-job.org 가 그 작업을 **자동으로 꺼 버릴 수 있습니다.** (문서: 연속 25회 이상 실패 시) 실패 알림 이메일을 놓치지 마세요.
- **GitHub Actions 일정 실행은 쓰지 않습니다.** 이 저장소는 비공개라 월 2,000분만 무료인데, 10분마다 돌리면 한 달에 4,320번이라 열흘 안에 바닥나고 **PR 검사(CI)까지 멈출 수 있습니다.**
- 결과는 지금 **서버 메모리**에 저장됩니다. 서버를 껐다 켜면 사라집니다. 진짜 결과(매일 밤 요약표, #34)는 DB 에 같은 규칙(날짜가 같으면 덮어쓰기)으로 저장합니다.

## 8. 막혔을 때

| 증상 | 이렇게 확인하세요 |
| ---- | ---------------- |
| `401` | 헤더 이름이 정확히 `X-Job-Key` 인지, 값이 Render 의 `JOB_SECRET_KEY` 와 **글자 하나까지 같은지**(앞뒤 공백·줄바꿈 주의), Render 에 키를 넣고 서버가 다시 시작됐는지 |
| 서버 로그에 "JOB_SECRET_KEY 가 비어 있어서 … 전부 거절" | Render 환경변수에 `JOB_SECRET_KEY` 가 없습니다. 6-1 을 하세요 |
| `404` | 주소 끝의 작업 이름이 맞는지. 지금 있는 작업은 `practice`, `habit-nudge` 두 개입니다 |
| `405` | `POST` 로 불러야 합니다 (브라우저 주소창으로 열면 `GET` 이라 안 됩니다) |
| `500` | 작업이 실패했습니다. 서버 로그에서 `[작업] … 실행에 실패했습니다` 를 찾으세요 (예외의 **종류**만 나옵니다) |
| 로그에 줄이 안 쌓임 | cron-job.org 실행 기록에서 응답 코드를 확인. 서버가 자고 있었다면 첫 요청이 시간 초과일 수 있습니다 |
| 같은 줄이 두 번 쌓임 | 알람이 두 곳에 있는지 확인. 두 번 불려도 결과는 안전하지만, 필요 없는 알람은 지우세요 |
