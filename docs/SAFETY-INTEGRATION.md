# 위기 표현 입력과 보호 조치 (#56)

체크인 저장은 `SafetyService.check`로 자유 입력 세 칸(기타 이유·약속 조건·약속 행동)을 검사합니다.
단어 목록에 걸리면 AI 호출·사용 한도와 관계없이 바로 보호 조치를 적용합니다.
AI가 켜져 있으면 단어 목록에 없는 글도 판단하며, `SAFE`라는 정확한 답 이외에는 보수적으로 보호합니다.
AI 실패·잘못된 응답도 보호 조치 사유가 될 수 있습니다. 임상적 위험 확정 판정이 아닙니다.
로컬처럼 AI가 꺼져 있는 환경에서는 단어 목록만 검사하므로 간접 표현을 놓칠 수 있습니다.

통화는 기존 단어 목록과 통화 정리 GPT의 `crisis` 결과를 사용하고, 감지되면 같은 `activate` 함수를 부릅니다.
통화 원문을 다시 GPT에 보내 중복 검사하지 않습니다. 통화 AI 장애 때의 기존 503/429 응답은 유지합니다.

## 적용되는 결과

- 관리 설정의 최대 강도를 즉시 0으로 낮추고 다음 날 강도를 올리기로 한 예약도 취소합니다.
- 앱 잠금 허용을 끕니다.
- 기존 `messages` 테이블에 RECOVERY 안내와 사용자·시각을 남깁니다. 감지 원문은 이 기록에 넣지 않습니다.
- 오늘을 포함한 7일 동안 다음 통화는 지지 모드, 오늘의 작전 넛지는 건너뛰기, STICK 저장은 거절합니다.
- 체크인 저장 응답에 `showHelp`, `helpMessage`, `helpLines`를 추가합니다. 통화 마무리 응답에도 `helpMessage`, `helpLines`를 추가합니다.

도움 연결 목록은 기존 `HelpLine.ALL`의 1388·109입니다. 안내 문구와 연결처는 전문가 검토(Project#8)가 필요합니다.
API 필드 추가는 기존 필드를 제거하지 않습니다. FE는 `showHelp`가 true이면 바로 안내를 표시해야 합니다.

번호는 2026-10-17 공식 안내에서 재확인했습니다:
[청소년1388 소개](https://www.1388.go.kr/OCC/YTOSP_SC_OYY_01),
[보건복지부 자살예방 정책·109 안내](https://www.mohw.go.kr/menu.es?mid=a10716040000).
[정부 청소년상담 안내](https://www.mogef.go.kr/cc/ccy/cc_ccy_f001.do)는 휴대전화에서 지역번호+1388을 안내합니다.
기존 번호 값을 재사용한 것이며, FE의 실제 전화 연결 방식과 기존 상세 문구(비밀 보장 포함)는 전문가 검토에서 함께 확인해야 합니다.

## 기존 자료를 재사용한 이유와 남은 범위

새 테이블을 임의 설계하지 않고 기존 관리 설정과 회복 메시지를 사용했습니다. 안전 판단의 GPT 호출은 기존 COACH 분류로 집계하여 같은 글 호출 한도와 비용을 적용합니다.
현재 보호 여부는 `SafetyService.HELP_MESSAGE`와 일치하는 회복 메시지를 찾습니다.
이 문자열을 바꾸거나 회복 메시지를 별도로 지우면 기존 감지 기록을 못 찾을 수 있으므로,
문구 변경 전에 별도 감지 기록 구조와 이전 방식을 팀에서 설계해야 합니다.

현재 서버에는 일기 저장 API와 채찍 대기열이 없습니다. 일기 API가 생기면 같은 검사·보호 함수를 연결하고,
예약 채찍 대기열이 생기면 감지 시 취소와 발송 직전 재검사를 구현해야 합니다.
이미 시작한 외부 푸시를 회수하거나 동시에 진행되는 발송을 원자적으로 취소하는 기능까지 보장하지 않습니다.
이 때문에 이 PR은 #56을 자동 종료하지 않습니다.

## 검증

`SafetyServiceTest`는 키워드 우선, 간접 표현 GPT 판정, AI 실패/한도 소진, 예약 강도 상승 취소,
감지 원문 미저장과 사용자별 보호 조회를 확인합니다.
`SafetyFlowTest`는 실제 체크인 HTTP 처리에서 도움 번호 응답, 내 강도 0 적용,
내 채찍 차단과 다른 사용자의 정상 동작을 확인합니다.

2026-10-17 로컬 실행(18056)에서 실제 HTTP로도 확인했습니다.
위기 표현 체크인 저장은 200과 `showHelp=true`, 한글 안내, 1388·109를 반환했고,
이후 설정 조회는 `maxCareLevel=0`, `allowFocusMode=false`, 예약 강도 상승 없음이었습니다.
잘못된 source는 400이었습니다. Swagger HTML과 OpenAPI 문서는 200이며 새 응답 필드를 포함합니다.
연결된 브라우저가 없어 Swagger UI의 버튼을 직접 누르는 검증은 하지 못했습니다.
