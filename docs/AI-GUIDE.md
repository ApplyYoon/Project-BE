# Claude Code 사용법

코딩이 처음이어도 이 프로젝트를 할 수 있게 만들어 둔 도구들입니다.

---

## 1. 시작하기

프로젝트 폴더에서:

```bash
claude
```

처음 실행하면 **"이 프로젝트의 MCP 서버를 사용할까요?"** 라고 물어봅니다 → **예**
그다음 `/setup` 을 한 번 치세요. JDK 21·빌드 확인부터 git 훅 켜기, GitHub 로그인까지 한 단계씩 확인해 줍니다.

---

## 2. 슬래시 명령어

`/` 를 치면 목록이 뜹니다.

| 명령                          | 하는 일                                                |
| ----------------------------- | ------------------------------------------------------ |
| `/setup`                      | 최초 세팅 — JDK 21·빌드 확인 + git 훅 + GitHub 로그인 + MCP |
| `/start 공부 계획 API 만들기` | **브랜치 이름 후보를 주고** 골라서 브랜치 생성 후 작업 |
| `/save`                       | 검사 + **커밋 메시지 자동 작성**                       |
| `/pr`                         | 푸시 + PR 생성 (**체크리스트 직접 검증해서 채움**)     |
| `/check`                      | 코드 정리 + 빌드 + 테스트를 한 번에                    |
| `/sync`                       | 팀원이 올린 최신 코드 가져오기                         |
| `/run`                        | 서버 켜기 (`http://localhost:8080/api/v1/health`)      |
| `/fix <에러 메시지>`          | 에러가 무슨 뜻인지 설명하고 같이 고치기                |

### 처음부터 PR까지 — 이 순서대로만 치면 됩니다

```
/setup                      ← 처음 한 번만
/start 과목 목록 API 만들기   ← 브랜치를 만들고 작업 시작
  (Claude 와 같이 코드 작성)
/run                        ← 서버를 켜서 직접 불러 보기
/check                      ← 검사
/save                       ← 저장(커밋)
/pr                         ← GitHub 에 올리기
```

막히면 `/fix <에러 메시지>` — 고치기 전에 무슨 뜻인지부터 설명해 줍니다.

## 4. 안전장치 — 2겹으로 막습니다

이 저장소는 **비공개 + 무료 요금제**라 GitHub 브랜치 보호를 켤 수 없습니다.
(설정하려 하면 "Upgrade to GitHub Pro" 가 나옵니다)
그래서 아래 두 겹이 **유일한 안전장치**입니다. 둘 다 내 컴퓨터 안에서 돌아갑니다.

| 층                | 언제 작동                      | 막는 범위                     | 뚫리는 경우                         |
| ----------------- | ------------------------------ | ----------------------------- | ----------------------------------- |
| ① Claude Code 훅  | **Claude 가** 명령을 실행할 때 | 거의 모든 위험 명령 (아래 표) | 학생이 터미널에 직접 칠 때          |
| ② git 훅          | **누가 치든** 커밋·푸시할 때   | 커밋·푸시 관련만              | 훅을 안 켰을 때, `--no-verify`      |

### ① Claude Code 훅 (`.claude/hooks/guard-git.sh`)

Claude 가 실행하는 모든 Bash 명령을 검사합니다.

| 막히는 것                                 | 왜                                    |
| ----------------------------------------- | ------------------------------------- |
| `main` / `develop` 에 직접 커밋·푸시      | 검토 없이 공용 코드가 바뀜            |
| `push --force` / `-f` / `origin +main`    | 원격 커밋을 덮어써 팀원 작업이 사라짐 |
| `push --mirror`                           | 내게 없는 원격 브랜치를 **전부 삭제** |
| `push --delete` / `-d` / `origin :브랜치` | 원격 브랜치가 사라짐                  |
| `push --prune`                            | 원격 브랜치가 무더기로 사라짐         |
| `reset --hard`                            | 저장 안 한 작업이 영원히 사라짐       |
| `clean -f` / `-fd` / `-fdx`               | 새로 만든 파일이 전부 삭제됨          |
| `checkout .` / `restore .`                | 저장 안 한 수정을 전부 버림           |
| `stash clear` / `stash drop`              | 치워둔 작업이 영구 삭제됨             |
| `filter-branch` / `filter-repo`           | 모든 커밋을 다시 써서 팀원과 어긋남   |
| `reflog expire` / `gc --prune`            | 마지막 복구 수단이 사라짐             |
| `update-ref -d` / `branch -d` / `-D`      | 브랜치가 기록 없이 사라짐             |
| `remote remove` / `set-url`               | 엉뚱한 저장소로 푸시됨                |
| `rm -rf .git`                             | 모든 커밋 기록이 사라짐               |
| `--no-verify` / `commit -n`               | git 훅(②)을 건너뜀                    |
| `core.hooksPath` 를 다른 곳으로 바꾸기    | git 훅(②)이 꺼짐                      |

평소 쓰는 명령은 그대로 통과합니다.
`git push -u origin feat/x`, `git stash pop`, `git checkout -- 파일`, `git clean -n`,
`git config core.hooksPath .githooks` 등.

`.env` 파일은 Claude 가 **읽지도 못하게** 막아 두었습니다. (`.claude/settings.json`)

### ② git 훅 (`.githooks/`)

터미널에 **직접** 쳐도 막힙니다. 단, **한 번 켜야** 동작합니다.

```bash
git config core.hooksPath .githooks
```

| 훅           | 하는 일                                                               |
| ------------ | --------------------------------------------------------------------- |
| `pre-commit` | main·develop 직접 커밋 차단 + `.env` 커밋 차단                        |
| `commit-msg` | 커밋 메시지가 `타입: 한국어 설명` 형식인지 검사                       |
| `pre-push`   | main·develop 직접 푸시, **강제 푸시**, 브랜치 삭제 푸시 차단          |

FE 는 husky(Node 도구)를 쓰지만, BE 는 자바 프로젝트라 Node 에 기대지 않도록 **순수 git 훅**(셸 스크립트)으로 만들었습니다.
그래서 `pnpm install` 같은 설치 과정 없이 위 명령 한 줄로 켭니다.

강제 푸시 판별 방법: git 은 `--force` 를 썼는지 알려주지 않습니다.
대신 **원격 커밋이 내 커밋의 조상이 아니면** 원격 기록을 덮어쓰는 것이므로 강제 푸시로 봅니다.
`--force`, `--force-with-lease`, `-f`, `origin +main`, `--mirror` 가 전부 여기에 걸립니다.

> ⚠️ `--no-verify` 를 붙이면 git 훅은 통째로 건너뛰어집니다. 절대 쓰지 마세요.
> 이 저장소에서는 서버 쪽 방어선이 없어서, 건너뛰면 그대로 `main` 에 들어갑니다.

## 5. MCP — 외부 서비스 연결

MCP 는 Claude 가 GitHub 같은 서비스를 **직접 다루게** 해주는 연결 통로입니다.

이 저장소에는 `.mcp.json` 이 들어 있어서 따로 설치할 필요가 없습니다.
`claude` 실행 시 "사용할까요?" 에 **예**를 누르면 됩니다.

| 이름     | 주소                                 | 뭘 할 수 있나                  |
| -------- | ------------------------------------ | ------------------------------ |
| `github` | `https://api.githubcopilot.com/mcp/` | 이슈·PR 읽고 만들기, 코드 검색 |

`github` 는 두 가지가 있어야 연결됩니다.

- 터미널에서 `gh auth login` 으로 GitHub 에 로그인돼 있을 것 (`/setup` 이 안내해 줍니다)
- **node** 가 설치돼 있을 것 — 연결할 때마다 `.claude/scripts/github-mcp-headers.mjs` 가
  gh 의 토큰을 꺼내 쓰는데, 이 스크립트가 node 로 돕니다.
  (GitHub 는 `/mcp` 의 Authenticate 버튼 로그인을 지원하지 않아서 이렇게 합니다)

배포 서비스가 정해지면 그 MCP 도 여기에 추가합니다.

### 연결 확인

```
/mcp
```

- 목록에 없으면 → Claude Code 를 껐다 켜고 다시 `/mcp`
- 연결 실패면 → 터미널에서 `gh auth status` 와 `node -v` 확인

### ⚠️ MCP 보안

- MCP 를 연결하면 그 서비스에서 **내 계정 권한 그대로** 동작합니다.
- 공식 주소가 맞는지 꼭 확인하세요. 비슷한 가짜 주소가 있을 수 있습니다.
- **출처를 모르는 MCP 서버는 붙이지 마세요.**
- MCP 없이도 이 프로젝트는 전부 동작합니다. 안 되면 GitHub 웹을 쓰면 됩니다.

## 7. AI가 준 코드를 그대로 믿지 마세요

- **이해 안 되는 코드는 "왜 이렇게 했는지 설명해줘" 라고 물어보세요.**
  설명을 못 하면 그 코드는 쓰지 않는 게 낫습니다.
- API 는 **직접 불러서** 확인하세요. 다른 사용자의 데이터가 보이지 않는지도 같이.
- AI도 틀립니다. 특히 GPT 가 만든 숫자는 믿지 말고, 숫자는 코드로 계산하세요.

> 이 프로젝트의 목적은 "AI가 만든 결과물"이 아니라
> **여러분이 만들고 설명할 수 있는 결과물**입니다.
