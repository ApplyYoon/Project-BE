# 요청·응답이 뭔가요? + Swagger 로 직접 불러 보기

API 를 만들었으면 **직접 불러 봐야** 잘 만들었는지 알 수 있습니다.
이 문서는 "요청", "응답" 이 처음인 사람을 위한 설명서입니다.

---

## 1. 요청과 응답

서버는 **식당**과 비슷합니다.

```
   손님(FE·브라우저)                         식당(우리 서버)
        │                                        │
        │ ── 요청: "메모 목록 주세요" ─────────▶ │
        │                                        │  (DB 에서 찾는 중)
        │ ◀── 응답: "여기요, 3개 있어요" ─────── │
```

- **요청(Request)**: 손님이 내는 주문서. "무엇을 해 달라" 는 말입니다.
- **응답(Response)**: 식당이 내주는 것. 음식(데이터)과 함께 "잘 됐다 / 안 됐다" 를 알려줍니다.
- **API**: 메뉴판에 있는 메뉴 하나. "이 주소로 이렇게 주문하면 이런 걸 줍니다" 라는 약속입니다.

### 요청에 들어가는 것

| 무엇 | 뜻 | 예 |
| --- | --- | --- |
| 방식(Method) | 무엇을 하고 싶은지 | `GET`, `POST` … (아래 표) |
| 주소(URL) | 어느 메뉴인지 | `/api/v1/memos` |
| 본문(Body) | 같이 보내는 내용 (있을 때만) | `{ "content": "수학 숙제" }` |

| 방식 | 하는 일 | 식당으로 치면 |
| --- | --- | --- |
| `GET` | 가져오기 | "메뉴 보여주세요" |
| `POST` | 새로 만들기 | "이거 하나 주문할게요" |
| `PATCH` | 일부 고치기 | "주문한 것 중 이것만 바꿔 주세요" |
| `DELETE` | 지우기 | "주문 취소할게요" |

### 응답에 들어가는 것

| 무엇 | 뜻 | 예 |
| --- | --- | --- |
| 상태 코드(Code) | 잘 됐는지 알려주는 번호 | `200` |
| 본문(Body) | 돌아온 내용 | `[{ "id": 1, "content": "수학 숙제" }]` |

| 번호 | 뜻 | 누구 잘못? |
| --- | --- | --- |
| `200` | 잘 됐어요 | — |
| `400` | 보낸 내용이 이상해요 (빈칸, 형식 틀림) | 보낸 쪽 |
| `401` | 누구인지 모르겠어요 (로그인 필요) | 보낸 쪽 |
| `404` | 그런 건 없어요 (주소 오타, 없는 번호) | 보낸 쪽 |
| `500` | 서버가 고장 났어요 | **서버 (우리 코드)** |

> **`400`·`404` 는 나쁜 게 아닙니다.** 잘못된 주문을 서버가 제대로 거절했다는 뜻입니다.
> 빈칸으로 보냈는데 `200` 이 나오거나 `500` 이 나오면 그게 문제입니다.

## 2. Swagger 로 불러 보기

Swagger(스웨거)는 우리 서버의 **메뉴판**입니다. 만든 API 가 전부 나오고, 버튼으로 직접 주문해 볼 수 있습니다.

### 순서

1. 서버를 켭니다. — `./gradlew bootRun` (Claude Code 에서는 `/run`)
2. 브라우저에서 👉 **http://localhost:8080/swagger-ui.html**
3. 불러 보고 싶은 API 를 눌러 펼칩니다.
4. 오른쪽의 **Try it out** 을 누릅니다. (눌러야 값을 넣을 수 있습니다)
5. 값을 넣어야 하는 칸이 있으면 채웁니다.
6. 파란 **Execute** 를 누릅니다. ← 이게 "요청 보내기" 입니다
7. 바로 아래 **Server response** 를 봅니다.
   - **Code**: 상태 코드 (`200` 이면 성공)
   - **Response body**: 돌아온 내용

가장 쉬운 것부터 해 보세요: **상태 확인** → `GET /api/v1/health` → Try it out → Execute → `{"status":"ok","db":"connected"}`

### 꼭 해 볼 것 3가지

API 를 만들었다면 잘 되는 경우만 보지 말고 **일부러 틀리게도** 보내 보세요.

| 해 볼 것 | 이렇게 나와야 합니다 |
| --- | --- |
| 제대로 보내기 | `200` + 원하는 내용 |
| 빈칸으로 보내기 / 이상한 값 넣기 | `400` |
| 없는 번호로 부르기 | `404` |

### 로그인이 필요한 API 라면

`401` 이 나오면 "누구인지 알려 달라" 는 뜻입니다.

1. Swagger 화면 오른쪽 위 **Authorize** (자물쇠) 를 누릅니다.
2. **테스트 토큰** `local-test-token` 을 붙여 넣고 **Authorize** → **Close**
3. 다시 Execute 하면 토큰이 같이 나갑니다.

토큰은 "나 누구예요" 를 증명하는 입장권입니다. 테스트 토큰은 **내 컴퓨터에서만** 통하는 연습용 입장권이고,
값은 `src/main/resources/application-local.yml` 의 `app.auth.test-token` 에 있습니다.
이 토큰으로 부르면 서버가 켜질 때 만들어 둔 **테스트 사용자(1번)** 로 로그인한 것으로 봅니다.

잘 들어갔는지는 **가입·로그인 → `GET /api/v1/auth/me`** 를 불러 보면 압니다. `{"id":"1","name":"테스트 사용자"}` 가 나오면 됩니다.

진짜 로그인을 해 보고 싶다면 `POST /api/v1/auth/signup` 으로 가입하고 `POST /api/v1/auth/login` 을 부른 뒤,
응답의 `token` 값을 Authorize 에 넣으면 됩니다. (로컬 DB 는 서버를 끄면 비워지므로 켤 때마다 다시 가입해야 합니다)

## 3. 자주 묻는 것

### 내가 만든 API 가 Swagger 에 안 보여요

- 서버를 **껐다가 다시** 켰나요? 코드를 고치면 다시 켜야 반영됩니다.
- Controller 클래스 위에 `@RestController` 가 있나요?
- 브라우저를 새로고침했나요?

### Swagger 에 영어로만 나와요

Controller 에 `@Tag(name = "메모")`, 메서드에 `@Operation(summary = "내 메모 목록")` 을 붙이면 한국어로 보입니다.

### `500` 이 나와요

서버 코드에서 에러가 난 것입니다. 서버를 켠 터미널에 빨간 글자가 길게 나옵니다.
그중 **`Caused by:`** 로 시작하는 줄이 진짜 원인입니다. Claude Code 에서 `/fix` 뒤에 그 줄을 붙여 넣어 보세요.

### Claude Code 에서 한 번에 하려면

`/swagger` 를 치면 서버를 켜고, API 를 대신 불러 본 뒤, 내가 직접 해 볼 순서를 알려줍니다.
