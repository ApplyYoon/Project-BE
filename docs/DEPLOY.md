## 2. 배포하기

### CI/CD 자동 연결

- GitHub Actions 설정은 저장소 루트의 `.github/workflows/ci.yml` 입니다. PR 생성/수정과 `main` push 에서만 포맷 검사·테스트·빌드를 실행합니다. `develop` push 는 실행하지 않습니다.
- Java 21 / Ubuntu 작업 하나를 사용하고, Gradle 의존성·배포판·빌드 결과를 캐시합니다. 같은 PR 에 새 커밋을 올리면 이전 실행을 취소하며, 한 실행은 최대 15분입니다.
- 같은 저장소의 PR 은 해당 PR 범위에 캐시를 저장하고 재사용합니다. 다른 PR 과 공유되지는 않습니다. 외부 fork PR 은 캐시를 읽기만 합니다.
- `render.yaml` 의 `autoDeployTrigger: checksPass` 는 `main` 커밋의 CI 완료 후 Render 가 자동으로 Docker 빌드·배포하도록 설정합니다. 별도 Deploy Hook, Render API 키, Actions 배포 작업은 필요하지 않습니다.
- 기존 서비스가 Blueprint 로 관리된다면 이 설정이 있는 `main` 의 Blueprint 를 동기화합니다. 대시보드에서 직접 만든 서비스라면 **Settings → Branch = main**, **Auto-Deploy → After CI Checks Pass** 를 설정합니다. 파일 수정만으로 기존 서비스 설정이 바뀌지는 않습니다.
- 먼저 백엔드 코드와 이 워크플로우가 `main` 에 있어야 합니다. `main` 이 초기 커밋뿐이면 배포 브랜치를 바로 전환하지 말고, 팀의 릴리스 절차로 코드를 반영한 뒤 전환합니다.
- 확인 순서: PR 의 `CI / check` 성공 → `main` 반영 후 해당 커밋의 CI 성공 → Render Events/Deploys 에 같은 커밋 배포 성공 확인. PR 성공만으로 운영 배포되지는 않습니다.
- CI 실패 또는 체크가 없는 커밋은 자동 배포되지 않습니다. 테스트는 H2 기반 `local` 프로필을 사용하며 운영 DB 비밀값은 GitHub 에 추가하지 않습니다.

공식 문서: [Render CI 연동](https://render.com/docs/deploys#integrating-with-ci), [Gradle Actions 캐시](https://github.com/gradle/actions/blob/v4/docs/setup-gradle.md).

### 2-1. Render 가입

1. https://render.com 에서 **GitHub 계정으로 가입**합니다.
2. ⚠️ **결제수단(카드)을 요구하면 멈추고 팀에 알려 주세요.** 카드 없이 쓰는 것이 이 이슈의 전제인데, 공식 문서에는 가입 때 카드가 필요한지 나와 있지 않아서 가입 화면에서만 확인할 수 있습니다.

### 2-2. 서버 만들기 (Blueprint)

1. Render 대시보드에서 **New → Blueprint** 를 누릅니다.
2. 저장소 **Project-BE** 를 고르고, 브랜치는 **`main`** 으로 합니다.
3. Render 가 저장소 맨 위의 [`render.yaml`](../render.yaml) 을 읽어서 서버 설정을 채워 줍니다. (이름 `project-be`, 무료, 싱가포르, Docker)
4. **값을 입력하라는 칸**이 여러 개 나옵니다. 아래 **4개는 꼭** 표대로 넣습니다. (나머지 칸은 표 아래 설명)

| 칸                     | 무엇을 넣나                                                                                          |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`         | `jdbc:postgresql://<Neon 호스트>/<DB 이름>?sslmode=require`  ← **`main`** 브랜치 것                  |
| `DATABASE_USERNAME`    | Neon 접속 정보의 사용자 이름                                                                         |
| `DATABASE_PASSWORD`    | Neon 접속 정보의 비밀번호                                                                            |
| `CORS_ALLOWED_ORIGINS` | 이 서버를 불러도 되는 FE 주소. 예: `https://내-fe.vercel.app` (끝에 `/` 없이)                        |

> **`DATABASE_URL` 만드는 법**
> Neon 콘솔 → 브랜치 `main` 고르기 → **Connect** → 언어 **Java** 를 고르면 접속 문자열이 나옵니다.
> 거기서 **호스트**와 **DB 이름**만 가져와 위 모양(`jdbc:postgresql://…`)으로 만듭니다.
> Neon 예시에는 `user=` · `password=` 가 주소 안에 들어 있지만, 우리 설정(`application-prod.yml`)은 사용자와 비밀번호를 따로 받으므로 **주소에서는 뺍니다.**
> 예시에 있는 `channelBinding=require` 가 우리 드라이버에도 필요한지는 확인하지 못했습니다. `"db":"error"` 가 나오면 붙여 보세요.
> `postgresql://` 로 시작하는 문자열을 그대로 붙이면 안 됩니다. 앞에 `jdbc:` 가 있어야 합니다.

5. **Apply** 를 눌러 만듭니다. 처음 배포는 시간이 걸립니다. (아래 [처음 켜지는 시간](#처음-켜지는-시간) 참고)

> **기능을 켜는 칸도 같이 나옵니다.** 아직 정하지 않았다면 비워 두고 넘어가도 됩니다. 비어 있으면 그 기능만 꺼진 채로 서버는 돌아갑니다.
>
> | 칸 | 무엇 | 자세히 |
> | --- | --- | --- |
> | `OPENAI_API_KEY`, `OPENAI_REALTIME_MODEL` | AI(GPT) 글 · 통화 | 아래 "AI(GPT) 켜기", "AI 통화 켜기" |
> | `JOB_SECRET_KEY` | 예약 작업 비밀 키 | [JOBS.md](./JOBS.md) "Render 에 키 넣기" |
> | `GOOGLE_CLIENT_ID` | 구글로 시작하기 | 아래 "구글 로그인 켜기" |
> | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | 웹 푸시 | 아래 "웹 푸시 켜기" |
>
> ⚠️ Render 화면이 빈칸을 허락하는지는 공식 문서에 없습니다. 빈칸으로 넘어갈 수 없으면 **아무 값이나 넣지 말고** 멈춘 뒤 팀에 알려 주세요. (특히 `JOB_SECRET_KEY` 에 대충 넣은 값은 누구나 맞힐 수 있는 키가 됩니다) 풀린 방법은 이 문서에 추가해 주세요.

### 🔒 비밀값 규칙

- `DATABASE_*` 값은 **Render 설정 화면에만** 입력합니다. 코드·`render.yaml`·이슈·PR·채팅·스크린샷에 쓰지 않습니다.
- `render.yaml` 의 `sync: false` 는 "값은 파일에 안 쓰고 Render 화면에서 직접 입력한다" 는 뜻입니다.
- 나중에 비밀값이 생기면(예: `OPENAI_API_KEY`) Render 서비스의 **Environment** 화면에서 직접 추가합니다. (Blueprint 는 처음 만들 때만 값을 물어봅니다)
- 실수로 어딘가에 적었다면 **바로 팀장에게 알리고 비밀번호·키를 새로 발급**하세요.

## 3. 잘 됐는지 확인하기 (완료 조건)

배포가 끝나면 Render 가 `https://project-be-xxxx.onrender.com` 같은 **주소**를 줍니다. 터미널에서:

```bash
curl -i https://<받은 주소>/api/v1/health
```

| 봐야 할 것         | 정상                                        |
| ------------------ | ------------------------------------------- |
| 첫 줄              | `HTTP/2 200` ← **이것이 완료 조건입니다**   |
| 본문               | `{"status":"ok","db":"connected"}`          |

- `"db":"connected"` 까지 봐야 합니다. **DB 에 못 붙어도 서버는 꺼지지 않고 `200` 을 줍니다.** (`"db":"error"`) 그래서 Render 의 상태 확인(`healthCheckPath`)은 통과해도 DB 는 안 붙은 채일 수 있습니다.
- 배포 서버에서는 Swagger 화면(`/swagger-ui.html`)이 꺼져 있습니다. 열리지 않는 게 정상입니다.

## 메모리 (왜 `JAVA_TOOL_OPTIONS` 가 있나)

무료 서버는 메모리가 **512MB** 뿐인데, 자바 서버는 아무 말이 없으면 메모리의 25% 정도만 쓰도록 정해져 있어 너무 작거나, 반대로 잘못 쓰면 서버가 강제로 꺼집니다. 그래서 `render.yaml` 에 시작값을 넣어 뒀습니다.

| 설정                        | 뜻                                                                            |
| --------------------------- | ----------------------------------------------------------------------------- |
| `-XX:MaxRAMPercentage=65`   | 자바가 쓸 수 있는 메모리를 서버 메모리의 65% 로 정함 (남겨 둘 몫이 있어야 안 꺼짐) |
| `-XX:+UseSerialGC`          | 메모리를 적게 쓰는 방식으로 쓰레기(안 쓰는 데이터)를 치움                      |
| `-XX:TieredStopAtLevel=1`   | 코드 최적화를 줄여서 켜질 때 CPU 와 메모리를 덜 씀                             |
| `-Xss512k`                  | 일꾼(스레드) 한 명이 쓰는 작업 공간을 줄임                                     |

> ⚠️ **이 값은 Render 에서 켜 본 값이 아닙니다.** 내 컴퓨터에서 메모리를 512MB 인 것처럼 제한해 켜 보니 켜진 직후 약 190MB 를 썼고, 기능이 늘어난 뒤(2026-10-17) 다시 재 보니 약 **240MB** 였습니다. (DB 가 안 붙은 상태였고, 요청을 20번 보내도 거의 늘지 않았습니다. 자바가 쓸 수 있는 최대 크기는 약 334MB 로 잡혔습니다.) 첫 배포 로그에서 `OutOfMemoryError` 나 "메모리 부족으로 재시작" 알림이 보이면 팀과 상의해서 고치세요.

## 처음 켜지는 시간

- 무료 서버의 CPU 는 **0.1** 입니다. 자바 서버는 켜질 때 CPU 를 많이 씁니다. 내 컴퓨터에서는 켜지는 동안 CPU 를 약 **15초** 썼고(2026-10-17, 벽시계로는 약 13초), CPU 가 0.1 이면 그 10배인 **2분 30초 이상, 길면 몇 분** 걸린다는 계산입니다. (추정이고, 컴퓨터마다 다릅니다. 기능이 늘수록 길어집니다)
- Render 는 새 서버가 상태 확인을 통과하기를 **15분까지** 기다리고, 그 안에 통과하지 못하면 배포를 취소합니다. 상태 확인 한 번은 **5초 안에** 대답해야 합니다. ([공식 문서](https://render.com/docs/health-checks)) 우리 `/api/v1/health` 는 DB 가 멈춰도 약 1초 안에 대답하도록 맞춰 뒀습니다. 배포가 실패로 끝나면 로그를 확인하세요.

## 잠드는 서버 (#9 에 영향)

- 무료 서버는 **15분 동안 요청이 없으면 잠들고**, 다시 요청이 오면 깨어나는 데 **약 1분** 걸립니다. 자바 서버는 깨어난 뒤 켜지는 시간이 더 걸릴 수 있습니다.
- 그래서 **정해진 시각에 서버 작업을 돌리는 기능(#9)은 서버가 자는 동안 실행되지 않습니다.** #9 를 만들 때 이 점을 같이 정해야 합니다.
- 무료 인스턴스는 월 **750시간**까지입니다. 서버 하나는 한 달 내내(744시간) 켜 둬도 되지만, 위처럼 요청이 없으면 잠듭니다. 다 쓰면 다음 달까지 멈춥니다.
- 무료 서버는 **파일을 저장해도 다시 배포하면 사라지고**, 메일 포트(25·465·587)로 나가는 연결이 막혀 있습니다. 데이터는 꼭 Neon 에 저장하세요.

## AI(GPT) 켜기

글 AI 기능(홈의 어제 한 줄 · 주간 · 월간 코치 문단, #87)은 **배포 서버에서만** 켜집니다. GPT 키의 자리가 배포 설정(`application-prod.yml`)에만 있어서,
내 컴퓨터에서는 환경변수를 넣어도 GPT 를 부르지 않습니다. 키가 여러 컴퓨터에 퍼지지 않게 하려는 것입니다.

Render 서비스의 **Environment** 화면에서 `OPENAI_API_KEY` 를 넣으면 켜집니다. 비어 있으면 꺼진 채로 돌아갑니다.

| 칸                        | 무엇을 넣나                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------- |
| `OPENAI_API_KEY`          | OpenAI 에서 받은 키. **이 화면에만** 입력합니다. 코드·문서·채팅 어디에도 적지 않습니다        |
| `OPENAI_MODEL`            | (선택) 글 모델의 이름. **안 넣으면 `gpt-6-luna`** 를 씁니다 (2026-10-11 에 정함)              |
| `AI_COST_WON_PER_TEXT_CALL` | (선택) 글 AI 한 번의 대략적인 비용(원). 기록용 어림값. 안 넣으면 `1` |

**모델** — 글 모델은 `gpt-6-luna` 로 정했습니다. 2026-10-11 가격표에서 최신 계열 중 가장 싼 모델입니다(100만 토큰당 입력 $0.10 · 출력 $0.50, 문단 하나에 1원이 안 됩니다).
코치 문단은 숫자 몇 개를 몇 문장으로 푸는 쉬운 일이고, 서버가 AI 의 답을 검사해서(지어낸 숫자·깎아내리는 말) 걸리면 버리고 기본 문장을 보여주기 때문에 작은 모델로 충분하다고 봤습니다.
말투가 어색하면 `OPENAI_MODEL` 에 다른 이름을 넣어 바꿉니다. 가격표: https://developers.openai.com/api/docs/pricing

**채팅 모델** — 상담 채팅만 2026-10-24 에 `gpt-6.1-sol` 로 올렸습니다(100만 토큰당 입력 $2 · 출력 $10, luna 의 약 20배).
학생과 직접 길게 이야기하는 곳이라 답의 질이 가장 잘 보이는 곳이어서입니다. 코치 문단 · 통화 요약 · 작은 AI 기능은 그대로 luna 입니다.
채팅 모델을 바꾸려면 Render 의 **Environment** 에 `OPENAI_CHAT_MODEL` 을 넣습니다. 안 넣으면 `gpt-6.1-sol` 이고, `OPENAI_MODEL` 을 바꿔도 채팅은 따라가지 않습니다.
대본이 길어서 답 한 번에 대략 10 ~ 20원으로 어림했습니다(어림값). 실제 요금은 OpenAI 사용량 화면에서 확인해 주세요.
큰 모델이라 답이 느릴 수 있어서, 서버가 채팅 답을 기다리는 시간을 15초 → 20초로 늘렸습니다(FE 는 25초까지 기다림).
⚠️ `gpt_usages` 의 비용 칸은 채팅도 `AI_COST_WON_PER_TEXT_CALL`(1원)로 적혀서, 채팅 비용이 실제보다 작게 보입니다.
모델 이름은 자주 바뀝니다. 없는 이름이 되면 GPT 가 거절하고, 앱은 기본 문장으로 계속 돌아갑니다. (로그에 `[AI] GPT 호출에 실패했어요`)

**켜졌는지 확인하기** — Render 의 로그에서 서버가 켜질 때 아래 줄 중 하나가 보입니다.

```
[AI] GPT 를 쓸 수 있어요. (키와 모델 이름이 설정돼 있습니다)
[AI] GPT 가 꺼져 있어요. 배포 서버에 OPENAI_API_KEY 가 있어야 켜집니다.
```

켜졌다면 FE 의 주간 리포트를 열어 코치 문단이 AI 문장으로 바뀌는지 봅니다. 로그에 `[AI] GPT 호출에 실패했어요` 가 보이면 키나 모델 이름이 틀렸거나 OpenAI 쪽 문제입니다.

> ⚠️ **진짜 GPT 를 불러 본 적은 아직 없습니다.** 부르는 방법은 OpenAI 공식 문서(Responses API, 2026-10-11)대로 만들었고, 가짜 서버로만 테스트했습니다.
> 첫 배포 때 위 순서로 꼭 확인해 주세요.

**돈 지키기** — OpenAI 계정에 **월 사용 한도**를 꼭 걸어 두세요. (이슈 #33 의 "사람이 확인" 항목입니다)
서버도 GPT 를 부를 때마다 `gpt_usages` 테이블에 사용자 · 종류 · 대략적인 비용을 기록합니다. (`domain/gpt/GptUsageGuard`)
한 사람의 하루 한도(글 호출 · 작은 AI 기능 · 통화 횟수 · 통화 시간 · 웹 검색)는 2026-10-24 에 모두 없앴습니다. (요금은 여유로운데 개인이 막혀서)
그래서 서버는 많이 쓰는 사람을 막지 않습니다. **OpenAI 월 사용 한도가 유일한 안전장치**입니다.
`AI_DAILY_LIMIT_PER_USER` · `AI_ASSIST_DAILY_LIMIT_PER_USER` · `AI_CALL_DAILY_LIMIT_PER_USER` · `AI_CALL_DAILY_MINUTES_PER_USER` · `AI_TUTOR_WEB_SEARCH_DAILY_LIMIT` 는 Render 에 남아 있어도 쓰이지 않으니 지워도 됩니다.

## AI 통화 켜기

AI 통화(#27)는 글 AI 와 **따로** 켭니다. 음성이 글보다 훨씬 비싸서, 음성 모델 이름을 일부러 넣어야만 켜지게 했습니다.
Render 의 **Environment** 에 아래를 넣습니다. `OPENAI_API_KEY` 는 위 "AI(GPT) 켜기" 에서 넣은 것을 같이 씁니다.

| 칸                             | 무엇을 넣나                                                                 |
| ------------------------------ | --------------------------------------------------------------------------- |
| `OPENAI_REALTIME_MODEL`        | 음성 통화용 모델 이름 (예: `gpt-realtime-2.1-mini`). **비워 두면 통화만 꺼집니다** |
| `OPENAI_REALTIME_VOICE`        | (선택) AI 의 목소리. 안 넣으면 `marin`                                      |
| `AI_CALL_MAX_SECONDS`          | (선택) 통화 한 번의 최대 길이(초). 안 넣으면 `180`(3분)                     |
| `AI_COST_WON_PER_CALL_MINUTE`  | (선택) 통화 1분의 대략적인 비용(원). 기록용 어림값. 안 넣으면 `80` (아래 큰 모델 3분 약 240원 기준) |

**비용 (2026-10-11 가격표 기준, 100만 토큰당)**

| 모델                    | 음성 입력 | 음성 출력 |
| ----------------------- | --------- | --------- |
| `gpt-realtime-2.1-mini` | $10       | $20       |
| `gpt-realtime-2.1`      | $32       | $64       |

3분 통화 한 번에 mini 는 **약 70 ~ 90원**, 큰 모델은 **약 210 ~ 240원** 으로 어림했습니다. (1달러 1,400원)
학생 30명이 매일 한 번씩 한 달이면 mini 로 약 7만 원, 큰 모델로 약 21만 원입니다.

> ⚠️ **위 금액은 어림값입니다.** "말하는 1분이 몇 토큰인지" 를 공식 문서로 확인하지 못하고 계산했습니다.
> 실제 요금은 통화를 몇 번 해 본 뒤 OpenAI 의 사용량 화면에서 확인하고, **월 사용 한도를 꼭 걸어 두세요.**

**돈이 새는 길과 막아 둔 것**

- 한 사람의 하루 통화 횟수 · 시간 한도는 2026-10-24 에 없앴습니다. 서버가 막지 않으니 OpenAI 월 한도가 꼭 있어야 합니다.
- 임시 키는 60초 안에 통화를 시작해야 쓸 수 있습니다.
- 통화 길이는 FE 가 `AI_CALL_MAX_SECONDS` 에서 끊습니다. **서버가 끊는 것이 아니라서**, 브라우저를 고쳐 쓰는 사람은 OpenAI 가 정한 최대 60분까지 이어갈 수 있습니다. 그래서 OpenAI 의 월 한도가 꼭 있어야 합니다.
  - 그렇게 길게 한 통화도 마무리를 부르면 **실제 시간(최대 60분)으로 기록**됩니다. (3분으로 줄여 적지 않습니다)
  - 마무리를 부르지 않은 통화는 시간을 알 수 없어서 통화 시간 칸이 비어 있습니다.
- 통화 횟수와 시간은 `gpt_usages` 테이블에 기록됩니다. (#33)

**켜졌는지 확인하기** — 서버가 켜질 때 로그에 아래 줄 중 하나가 보입니다.

```
[AI 통화] 켜져 있어요. (키와 음성 모델 이름이 설정돼 있습니다)
[AI 통화] 꺼져 있어요. 배포 서버에 OPENAI_API_KEY 와 OPENAI_REALTIME_MODEL 이 있어야 켜집니다.
```

> ⚠️ **진짜 통화는 아직 한 번도 해 보지 못했습니다.** 부르는 방법은 OpenAI 공식 문서(2026-10-11)대로 만들었고 가짜 서버로만 테스트했습니다.
> 첫 배포 때 직접 통화해 보고, 로그에 `[AI 통화] 임시 키를 받지 못했어요` 가 보이면 키나 모델 이름을 확인해 주세요.
> 시험하는 순서와 결과를 적는 칸은 [REALTIME-TEST.md](./REALTIME-TEST.md) 에 있습니다. (이슈 #26)

## 구글 로그인 켜기

FE 의 [Google로 시작하기](이슈 #19 · FE #319)를 켭니다. **비밀값이 아닙니다.** FE 의 `VITE_GOOGLE_CLIENT_ID` 와 같은 값입니다.

1. Render 의 Environment 에 `GOOGLE_CLIENT_ID` = 구글 클라우드 콘솔에서 만든 웹 클라이언트 ID (`….apps.googleusercontent.com`) 를 넣습니다.
2. 구글 클라우드 콘솔의 클라이언트 › **승인된 JavaScript 원본** 에 FE 배포 주소(`https://project-fe-swart.vercel.app`)가 있어야 합니다.
3. 콘솔이 **테스트 모드**라서, 콘솔의 "테스트 사용자" 에 넣은 구글 계정만 구글로 시작할 수 있습니다.

- 비어 있으면 서버 로그에 `[구글 로그인] 꺼져 있어요` 가 찍히고, 구글 로그인 API 가 503 을 돌려줍니다.
- 내 컴퓨터(`local`)는 `application-local.yml` 에 클라이언트 ID 가 들어 있어서 따로 넣지 않아도 됩니다.
- client secret 은 쓰지 않습니다. 콘솔에서 보이더라도 어디에도 넣지 마세요.

## 웹 푸시 켜기

앱을 닫아 둬도 휴대폰 알림 칸에 뜨는 **푸시 알림**(#32)을 켭니다. VAPID 키 한 쌍(공개 키 · 개인 키)이 필요합니다.

**1. 키 만들기 (내 컴퓨터에서 한 번)** — FE 를 하느라 Node.js 가 깔려 있으면 아래 한 줄이면 됩니다.

```bash
npx web-push generate-vapid-keys
```

`Public Key` 와 `Private Key` 가 한 줄씩 나옵니다. **개인 키는 어디에도 붙여 넣지 말고** 바로 아래 Render 화면에만 넣습니다.

**2. Render 의 Environment 에 넣기**

| 칸 | 무엇을 넣나 |
| --- | --- |
| `VAPID_PUBLIC_KEY` | 위에서 나온 `Public Key` |
| `VAPID_PRIVATE_KEY` | 위에서 나온 `Private Key` — 🔒 **비밀값**. 새면 남이 우리 학생들에게 알림을 보낼 수 있습니다 |
| `PUSH_SUBJECT` | (선택) 알림을 보내는 쪽의 연락처. `mailto:선생님메일` 이나 웹 주소. 안 넣으면 우리 GitHub 주소 |

- 키를 **한 번 정하면 바꾸지 않습니다.** 바꾸면 이미 알림을 켠 학생들의 구독이 모두 쓸모없어져서, 다시 켜야 합니다.
- 키는 둘 다 있어야 켜집니다. 하나라도 비었거나 모양이 틀리면 푸시만 꺼지고 서버는 그대로 돕니다.

**3. 켜졌는지 확인하기** — 서버가 켜질 때 로그에 아래 줄 중 하나가 보입니다.

```
[푸시] 웹 푸시를 보낼 수 있어요. (VAPID 키가 설정돼 있습니다)
[푸시] 웹 푸시가 꺼져 있어요. 배포 서버에 VAPID_PUBLIC_KEY 와 VAPID_PRIVATE_KEY 가 있어야 켜집니다.
```

**📱 기기별로 받을 수 있는 조건**

| 기기 | 앱을 닫아도 알림 | 조건 |
| --- | --- | --- |
| 안드로이드 (크롬 등) | ✅ | 알림 허용만 하면 됩니다. 홈 화면 설치는 필수가 아닙니다 |
| **아이폰 · 아이패드** | ✅ (iOS 16.4 이상) | **홈 화면에 추가한 앱에서만** 됩니다. 사파리 탭에서는 오지 않습니다. 알림 허용도 그 앱 안에서 버튼을 눌러야 물어봅니다 |
| PC (크롬 · 엣지 · 사파리) | ✅ | 브라우저가 켜져 있어야 합니다 |

- 도착 시각은 보장되지 않습니다. 배터리 절약 모드나 휴대폰 설정에 따라 늦거나 묶여서 올 수 있습니다.
- 학생이 알림을 한 번 거부하면, 다시 켜는 것은 휴대폰(브라우저) 설정에서 직접 해야 합니다.

> ⚠️ **진짜 휴대폰으로는 아직 받아 보지 못했습니다.** 암호화와 서명은 테스트 안에서 만든 키와 가짜 푸시 서버로만 확인했습니다. 첫 배포 때 안드로이드와 아이폰(홈 화면 앱)에서 한 번씩 받아 봐 주세요.

## 로그인이 느릴 때 (비밀번호 계산)

가입·로그인은 비밀번호를 **일부러 느리게** 계산합니다. (`PasswordHasher` — 같은 계산을 21만 번 되풀이)
훔친 DB 로 비밀번호를 맞혀 보는 공격을 느리게 만들기 위해서인데, 서버가 느리면 로그인도 같이 느려집니다.

개발 컴퓨터(애플 M 시리즈)에서 잰 로그인 한 번의 계산 시간입니다.

| 자바 실행 옵션                                        | 걸린 시간 |
| ----------------------------------------------------- | --------- |
| 기본                                                  | 약 0.13초 |
| `-XX:TieredStopAtLevel=1` (지금 `render.yaml` 의 설정) | 약 0.78초 |

> ⚠️ **Render 에서 재 본 값이 아닙니다.** 무료 서버는 CPU 가 0.1 이라 위 시간의 **10배 이상**(8초 이상) 걸린다는 계산이고,
> FE 는 10초 안에 답이 없으면 실패로 봅니다. 첫 배포 때 **가입·로그인이 몇 초 걸리는지 꼭 재 보세요.**

너무 느리면 둘 중 하나를 팀과 정합니다.

1. **되풀이 횟수 낮추기** — Render 의 Environment 에 `PASSWORD_HASH_ITERATIONS` 를 넣습니다. (기본 `210000`, 최소 `10000`)
   낮출수록 빨라지지만 그만큼 비밀번호를 맞혀 보는 공격도 쉬워집니다. 횟수를 바꿔도 **이미 가입한 사람은 그대로 로그인됩니다.** (저장된 값마다 쓴 횟수가 적혀 있습니다)
2. **`JAVA_TOOL_OPTIONS` 에서 `-XX:TieredStopAtLevel=1` 빼기** — 위 표처럼 계산이 약 6배 빨라집니다.
   대신 서버가 켜질 때 CPU 와 메모리를 더 씁니다. (얼마나 더 쓰는지는 재 보지 않았습니다. 위의 "메모리" 를 같이 보세요)
