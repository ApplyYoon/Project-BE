# 인사이트 고르기 (점수 식과 가중치)

분석(#36 ~ #40)이 규칙으로 만든 **인사이트 후보**에 점수를 매겨, 화면에 보여 줄 **1~2개**를 고르는 규칙입니다. (이슈 #41, 기획서 v2 3장 「'아하' 인사이트 고르기」)
핵심 사용자 경험 "이 앱이 나보다 나를 더 잘 아네?" 가 여기서 정해집니다.

- 코드: `domain/insight/InsightPicker.java` (값만 계산하는 함수, DB 를 쓰지 않음)
- 테스트: `domain/insight/InsightPickerTest.java` (아래 표의 숫자를 그대로 확인)
- 점수 식과 가중치는 **담당 학생이 정했습니다.** 바꿀 때는 이 문서·코드·테스트를 같이 고칩니다.

## 1. 네 기준 (각 0 ~ 100점)

| 기준 | 점수 | 매기는 법 |
| --- | --- | --- |
| **의외성** | 100 / 50 / 0 | 온보딩 때 스스로 말한 것과 **다르면 100** · 온보딩 답이 없어 **모르면 50** · **같으면 0** |
| **확실성** | 0 ~ 100 | **기록 일수 50점 + 차이 크기 50점** |
| | | 기록 일수: 비교하는 조건 중 **적은 쪽의 일수**. 14일이면 50점 만점 (7일이면 25점) |
| | | 차이 크기: 두 조건의 차이(%). **50% 이상이면 50점 만점** (20% 면 20점) |
| **실행 가능성** | 100 / 0 | 다음에 **해 볼 행동 하나**가 붙어 있으면 100 · 없으면 0 |
| **새로움** | 100 / 50 / 0 | 한 번도 말하지 않았으면 **100** · 마지막으로 말한 지 **4주(28일) 이상이면 50** · 4주 안에 말했으면 **0** |

## 2. 총점

```
총점 = 의외성 × 0.4 + 확실성 × 0.3 + 실행 가능성 × 0.2 + 새로움 × 0.1
```

| 기준 | 가중치 |
| --- | --- |
| 의외성 | **40** |
| 확실성 | **30** |
| 실행 가능성 | **20** |
| 새로움 | **10** |

> **왜 이렇게 나눴나요?** "놀라우면 기억에 남고, 틀리면 믿음을 잃으니" 의외성과 확실성을 크게 봤습니다. (담당 학생)

- 점수는 소수로 더한 뒤 **마지막에 한 번만 반올림**합니다. (확실성도 마찬가지)
- 총점이 높은 순서로 **최대 2개**를 고릅니다. 총점이 같으면 확실성이 높은 쪽, 그것도 같으면 종류 이름(`key`) 순서입니다.

## 3. 반응 버튼이 다음 선정에 반영되는 법 (#43)

지난번에 **같은 종류(`key`)** 의 인사이트에 누른 마지막 반응을 봅니다.

| 지난번 반응 | 다음 선정 |
| --- | --- |
| 몰랐는데 맞아 (`surprised`) | 총점 **+10** (100 을 넘지 않음) |
| 이미 알던 거야 (`alreadyKnew`) | **그대로** |
| 틀렸어 (`wrong`) | **고르지 않음** — 같은 틀린 말을 반복하지 않아서 믿음을 지킵니다 |

## 4. 그 밖의 규칙

- **근거 날짜가 하나도 없는 후보는 고르지 않습니다.** 모든 인사이트에는 근거 날짜가 붙습니다. (근거 줄은 `InsightEvidence.rowsOf`)
- 비교하는 조건 중 하나라도 **5일 미만이면 "가설"** 로만 나갑니다. 고르는 데서 빼지는 않고, 확실성 점수가 낮아집니다. (`InsightEvidence.isHypothesis`)
