# 딴짓하고 안 돌아올 때 알림 (설계 · 아직 만들지 않음)

공부 타이머를 켜 둔 채 다른 앱으로 나가서 **몇 분이 지나도 안 돌아오면**, 휴대폰 알림으로 한 번 "돌아올래?" 를 보내는 기능의 설계입니다.

> 📝 **이 문서는 설계만 적은 것입니다. 코드는 아직 없습니다.** (2026-10-15 선생님: "문서화까지만")
> 만들 사람은 이 문서의 순서대로 만들고, 맨 아래 "팀이 정할 것" 을 먼저 정해 주세요.
> 바탕이 되는 웹 푸시는 이미 있습니다: BE #166 (구독 · 보내기), #167 (예약 작업으로 보내기), FE #312 (알림 받기 버튼).

## 1. 지금 있는 것과 없는 것

| | 있음 / 없음 | 어디 |
| --- | --- | --- |
| 나간 횟수 세기 · 나가 있던 시간은 순공에서 빼기 | ✅ 있음 | FE `src/hooks/useAwayDetection.ts` |
| 집중 모드 중 **나가는 바로 그 순간** "돌아와" 알림 | ✅ 있음 | FE #305 (`showFocusLeaveNotification`) |
| 나간 뒤 **몇 분이 지나도 안 돌아오면** 한 번 더 알림 | ❌ 없음 | ← 이 문서 |

## 2. 왜 웹 페이지만으로는 안 되나

- 휴대폰은 화면을 벗어난 페이지의 코드를 **곧 멈춥니다.** "5분 뒤에 알림" 같은 타이머가 돌지 않습니다.
- 정해 둔 시각에 알림을 띄우는 브라우저 기능(Notification Triggers)은 크롬이 실험하다가 **그만두었습니다.**
- 그래서 **나갔다는 사실을 서버에 알리고, 서버가 몇 분 뒤에 푸시를 보내야** 합니다. 푸시는 앱이 멈춰 있어도 서비스 워커가 깨어나 띄웁니다. (FE `public/sw.js` 의 `push`)

## 3. 흐름

```
[학생 휴대폰]                                    [서버]
타이머가 흐르는 중 · 다른 앱으로 나감
  └─ visibilitychange (hidden)
     └─ POST /api/v1/away/leave  (keepalive) ──▶ away_events 에 한 줄: left_at = 지금
                                                    │
                                    cron-job.org 가 5분마다 ──▶ POST /api/v1/jobs/away-reminder
                                                    │   left_at 이 5분 넘게 지났고
                                                    │   returned_at 도 reminded_at 도 비어 있으면
                                                    └─▶ 푸시 "타이머 켜 둔 채로 나갔어. 돌아올래?"  → reminded_at = 지금
돌아옴
  └─ visibilitychange (visible)
     └─ POST /api/v1/away/return ──────────────▶ returned_at = 지금 (아직 안 보냈으면 이제 안 보냄)
```

### 만들 때 꼭 알아 둘 것

- **나갈 때 보내는 요청은 `fetch(…, { keepalive: true })` 로 보냅니다.** 페이지가 숨겨지는 순간이라 보통 요청은 중간에 끊길 수 있습니다.
  `navigator.sendBeacon` 은 **로그인 토큰(Authorization 헤더)을 붙일 수 없어서** 쓰지 못합니다.
- 나갈 때 요청이 못 가거나(배터리·인터넷), 돌아올 때 요청이 못 갈 수 있습니다. 그래서 **나간 지 60분이 넘은 줄은 보내지 않고 버립니다.** (오래된 기록으로 밤늦게 알림이 가지 않게)
- `visibilitychange` 는 **이미 `useAwayDetection` 이 듣고 있습니다.** 새로 듣지 말고 그 훅의 "나간 순간 · 돌아온 순간" 함수(`onLeave` · `onReturn`)에 서버 요청을 더합니다.

## 4. 서버에 만들 것

| 무엇 | 내용 |
| --- | --- |
| 테이블 `away_events` | `id`, `user_id`, `left_at`, `returned_at`(비어 있을 수 있음), `reminded_at`(비어 있을 수 있음). **어느 앱으로 갔는지는 저장하지 않습니다** (알 수도 없고, 모을 필요도 없습니다) |
| `POST /api/v1/away/leave` | 한 줄 만들기. 이미 안 돌아온 줄이 있으면 새로 만들지 않습니다 (두 번 와도 한 줄) |
| `POST /api/v1/away/return` | 가장 최근의 안 돌아온 줄에 `returned_at` 채우기. 없으면 아무 일도 안 함 |
| 예약 작업 `away-reminder` | 5분마다. 아래 "보내는 규칙" 대로 보내고 `reminded_at` 채우기 |

**보내는 규칙** (위에서부터, 하나라도 걸리면 안 보냄)

1. 연락 금지 시간(밤 11시 ~ 아침 7시) — `QuietHours`
2. 최근 7일 안에 위기 표현이 감지된 통화가 있음 — 공부 재촉을 멈춥니다 (`HabitNudgeJob` 과 같은 규칙)
3. 나간 지 5분이 안 됐거나, 60분이 넘었음
4. 이미 돌아왔거나(`returned_at`), 이미 보냈음(`reminded_at`) — **나간 한 번에 알림은 한 번만**
5. 오늘(새벽 4시 기준) 이 알림을 이미 **3번** 보냈음 — 하루에 너무 많이 울리지 않게

**알림 문장** — 탓하지 않고, 행동만 말합니다. (`ToneGuide`)

- ✅ "타이머 켜 둔 채로 나갔어. 5분만 더 해 볼까?"
- ❌ "또 딴짓했네" · "집중력이 없어" (사람을 깎아내림)
- 누르면 타이머(`/timer`)가 열립니다. 앱 알림 목록(messages)에는 남기지 않습니다. (하루에 여러 번이라 목록이 지저분해져서)

## 5. 조심할 것

- ⚠️ **휴대폰 화면을 꺼도 "나갔다" 로 잡힙니다.** (`document.hidden` 이 true) 폰을 잠그고 종이 책으로 공부하는 학생은 좋은 공부를 하는 중인데 "돌아와" 알림을 받게 됩니다. 아래 "팀이 정할 것" 1번을 꼭 먼저 정하세요.
- **노는 타이머(노는 계획)** 중에는 보내지 않습니다. FE 가 공부 타이머일 때만 `leave` 를 보냅니다.
- 직접 일시정지해 둔 상태에서 나간 것은 딴짓이 아니라서 보내지 않습니다. (`useAwayDetection` 의 지금 규칙과 같게)
- 5분마다 부르는 예약 작업이 있으면 **무료 서버가 잠들 틈이 없습니다.** (`docs/JOBS.md` 7번) 무료 사용 시간을 확인하세요.
- 나간 · 돌아온 시각은 학생의 행동 기록이라, 탈퇴하면 같이 지워져야 합니다. `away_events` 에 `user_id` 가 있으면 지금 탈퇴 코드가 저절로 지웁니다. (`AccountService.withdraw`)

3. **FE** — `useAwayDetection` 의 나간 순간 · 돌아온 순간에 서버 요청 더하기 (공부 타이머일 때만, `keepalive`)
4. **사람** — cron-job.org 에 `away-reminder` 를 5분마다 등록, 휴대폰으로 실제로 받아 보기

## 7. 팀이 정할 것

1. **화면을 끄고 공부하는 경우를 어떻게 할까요?** (가장 중요)
   - (가) 집중 모드일 때만 보낸다 — 집중 모드는 "화면을 켜 두겠다" 는 약속이라서
   - (나) 설정에 "폰 잠그고 공부할 때는 알림 끄기" 를 둔다
   - (다) 처음 한 번 나갔을 때 "공부 중이야? / 딴짓 중이야?" 를 묻고 기억한다
2. 몇 분 뒤에 보낼까요? (제안: 5분. cron 이 5분마다라서 실제로는 5 ~ 10분 뒤에 갑니다)
3. 하루 최대 몇 번? (제안: 3번)
4. 학생이 설정에서 이 알림만 따로 끌 수 있게 할까요? (제안: 그렇게 한다. 관리 설정 #22 과 같이)
