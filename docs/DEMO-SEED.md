## 왜 넣었나

발표 피드백에서 "AI 분석이 안 보인다" 는 말이 나왔습니다. 가입한 계정들(모두 팀원 · 테스트용, 개인정보 없음)에 기록이 거의 없어서,
서버가 분석할 거리가 없었습니다. 그래서 **가입자 전원(실행 때 12명)에게 6개월치 기록을 SQL 로 넣었습니다.** (사용자 결정)
"실제로 앱을 쓴 것처럼" 보이도록 세션의 일시정지 · 체크 · 메모, 시험 · 회고까지 채웠습니다.

### 서로 맞물리게 넣은 규칙

- **카드 하루치마다 결과를 먼저 하나 정하고**(했음 · 일찍 끝냄 · 미룸 · 실패), 세션 · 미루기/실패 표시 · 다음 날 체크인 사유 · 관리 단계 · 통화 요약 · 다음 날 아침 AI 메시지 · 주간 목표 판정이 모두 그 결과를 씁니다.
  그래서 "계획된 카드 하루치 6,552개 = 공부 세션 4,636 + 미루기/실패 1,916" 이 정확히 맞습니다.
- 무작위가 아니라 `md5(사람 · 날짜 · 카드)` 로 정해지는 값을 씁니다. 같은 날 다시 실행하면 같은 데이터가 나옵니다.
- 사람마다 **아침형 / 저녁형**, **폰에 약한 정도**가 정해져 있어서 6개월 내내 같은 습관을 보입니다.
- 밤 카드는 폰 때문에 놓치는 일이 많고, 아픈 날(한 달에 한 번쯤)은 그날 카드를 모두 놓칩니다.
- 이미 사람이 남긴 체크인 · 신호 · 관리 단계 · 주간 목표 · 회고가 있는 날짜(주)는 건드리지 않았습니다.

### 알아 둘 점

- **넣은 줄의 번호는 운영 DB 의 `seed_6m_rows` 표에 적혀 있습니다.** (엔티티가 없는 표라 `db/schema.sql` 에는 없습니다) 이 표를 지우면 넣은 줄만 골라 지울 수 없게 되니 지우지 마세요.
- 가상 카드 7장 · 과목 3개 · 고정 일정 2개는 FE 가 서버와 맞추면서 **가입자 모두의 앱 화면(오늘 계획 · 카드 목록 등)에 나타납니다.**
- FE 의 기록 탭 · AI 분석 카드는 그 기기에 저장된 기록을 읽습니다. 서버의 공부 기록은 기기로 내려가지 않아서(FE `lib/sessionSync.ts`), 이 데이터는 **서버 쪽 분석(인사이트 · 위험 예측 · 통화 · 코치 AI 등)에만** 쓰입니다.
- 다시 실행하면 지난번에 넣은 것을 먼저 지우고 다시 넣습니다. 두 벌이 되지 않습니다. 날짜는 실행한 날 기준으로 다시 정해집니다.
- 넣은 뒤에 DB 모양이 바뀌면(새 필수 칸 등) 이 SQL 은 그대로 안 돌 수 있습니다. 2026-10-24 의 `main` 모양 기준입니다.

## 넣는 법 (다시 넣을 때)

1. Neon 콘솔 → `project-be-render` → 브랜치 고르기 → **SQL Editor**
2. `db/seeds/seed-6m.sql` 전체를 붙여 넣고 **Run**
3. 맨 아래 결과 표(`tbl` / `rows_added`)에 표마다 몇 줄 들어갔는지 나옵니다.

전체가 `begin … commit` 으로 묶여 있어서, 중간에 에러가 나면 아무것도 바뀌지 않습니다.

## 지우는 법

1. Neon 콘솔 → `project-be-render` → 브랜치 **main** → **SQL Editor**
2. `db/seeds/seed-6m-remove.sql` 전체를 붙여 넣고 **Run**
3. 확인: 아래가 에러(`relation "seed_6m_rows" does not exist`)면 다 지워진 것입니다.

```sql
select count(*) from seed_6m_rows;
```

- `seed_6m_rows` 에 적힌 줄과, 가상 카드로 잰 세션 · 미루기 표시만 지웁니다. 사람이 직접 만든 기록은 남습니다.
- 가상 과목(국어 · 영어 · 수학)은 사람이 그 과목으로 세션 · 계획 · 점수를 남겼으면 지우지 않고 남깁니다.
- 지운 뒤 앱에서 가상 카드 등이 사라지는 것은 각 기기가 서버와 다시 맞출 때입니다. (앱을 다시 열면 됨)
